## 三、必须写进结论的三件事

**1. 头顶优势的大半来自"拒答"，不是来自"答得好"。**

16 条越界样本上，三个基线全部得 0（它们没有交互控制，一律作答），方法得 1.000，
仅此一项就贡献 16/200 = 0.08 的整体成功率。剔除后，方法对基线B、C 的领先从
+0.100 / +0.095 降到 +0.022 / +0.016，**均不再显著**。

**2. H3（交互控制）成立；H1（流程中间表示提升步骤与材料覆盖）不成立。**

- H3：响应方式准确率 0.28 → 0.565，追问正确率 0.84 → 0.95，Holm 校正后仍显著。
- H1：方法的步骤覆盖（0.7565）**低于**基线B（0.8021）与基线C（0.7926）；
  声明覆盖（0.7423）同样低于两者。加入流程骨架与断言核验后，内容覆盖**变差了**。

对 H1 为负的一个可解释机制：断言核验会删除证据不能逐字支撑的内容，回答因此变短、
覆盖下降，而当前指标以"覆盖"为主，于是核验的收益（更少无据断言）无法在这一指标上体现。
这属于**指标与机制不匹配**，或流程中间表示在这批数据上确实没有增益，两种解释目前无法区分。
**必须承认：以现有证据，不能宣称流程中间表示带来了收益。**

**3. 失效层分布：瓶颈已经从检索转到生成。**

| 配置 | 最早失效层分布（样本数） |
|---|---|
| 基线A | 生成 88、检索 72、流程 38、交互 2 |
| 基线B | 生成 118、检索 47、流程 29、交互 5 |
| 基线C | 生成 135、流程 34、检索 30、交互 1 |
| 方法 | **生成 132**、流程 38、检索 30、交互 0 |

方法已经没有交互层失败，检索层失败 30 条，**生成层 132 条是主瓶颈**。

## 七、结论

- 方法相对**朴素 RAG（基线A）**有显著且稳健的提升，这一点可以写。
- 方法相对**较强基线（B、C）**的整体提升不显著，且**内容覆盖显著更差**，这一点必须写。
- 目前有实证支持的唯一机制是**交互控制（追问/拒答/版本限定）**，其中拒答完全成立、
  追问的槽位判定仍是短板、版本限定完全未成立。
- 下一步的主攻方向是**生成层**（132/200 的最早失效点）与**对象限定 / 缺失槽位判定**，
  而非继续增强检索。
