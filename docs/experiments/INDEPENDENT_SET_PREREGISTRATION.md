# 独立确认性验证集：预注册

日期：2026-10-15（**在生成任何结果之前登记**）

---

## 一、为什么需要这一套

现有的 200 条评测样本已用于规则与提示词的迭代（那批正则就是照着它的问法写出来的），
其上的任何数字只能算**探索性**。以它为据宣称方法有效，等于在已见过的题上再考一遍。

独立确认性验证集的作用是给出唯一可以对外称为"结论"的数字。它的有效性来自两点：
样本在方法定型前生成，指标与判定规则在跑之前登记。

## 二、样本规格

| 项 | 规格 |
|---|---|
| 规模 | 120 条 |
| 事项覆盖 | 8 类，每类 15 条 |
| 场景覆盖 | 直接问答 20、条件缺失 20、对象错配 15、步骤错误 15、材料混淆 15、版本冲突 15、越界 10、多轮 10 |
| 字段契约 | 与开发集一致（复用 `data/schemas/`，评分与运行器不改） |
| 出题来源 | 只读官方证据与流程记录，**不看任何方法输出** |
| 新知识保证 | 记录实际数量，见下节修正说明 |
| 问法 | 不沿用开发集措辞，改为口语化、省略式、指代式与跨条件组合 |

### 修正说明（2026-10-15，生成样本之后、运行任何对照之前）

原定"至少 60 条的金标准支撑证据包含开发集从未引用的证据"。实际生成时发现一个数据层限制：
**金标准必须挂在流程记录的允许声明上，而声明只覆盖了部分证据。**

| 事项 | 证据总数 | 被流程记录覆盖 | 未覆盖 |
|---|---:|---:|---:|
| 成绩与证明打印 | 80 | 6 | 74 |
| 休学复学与学籍状态 | 56 | 6 | 50 |
| 退学办理 | 113 | 111 | 2 |
| 学历学位证书补办 | 21 | 21 | 0 |
| 其余四类 | 39 | 39 | 0 |

因此成绩证明与休学复学两类无法生成"基于未引用证据"的题目，实际达到 30 条（全部来自退学办理与证书补办）。

**修正后的保证**：题级独立性仍然硬性保证（120 条问句全新，且通过下述两道污染检查）；
证据新鲜度改为**记录并逐事项报告**，作为加强项而非硬门槛。
补齐成绩证明与休学复学两类的声明覆盖已列入 B2，完成后可扩充这一部分。
本修正发生在任何系统在本集合上运行之前，未参考任何模型输出。

### 污染控制

生成后与开发集做两道检查，任一不过则重出该题：

1. **文件级**：样本不复制开发集问句（字符 3-gram Jaccard 相似度上限 0.6）。
2. **语义级**：问句向量与任一开发集问句的余弦相似度上限 0.85（与开发集的语义泄漏审计同一工具与量纲）。

集内另加一道检查：**同一事项同一场景内**的问句，字符 3-gram Jaccard 上限 0.6、余弦上限 0.95。
限定在同一分格内比较，是因为只覆盖单个槽位的事项（成绩证明的办理类型、请假的天数等）
其三道条件缺失题在语义上必然接近，这道检查的目的是防止同一分格内重复凑数，不是强求措辞改写。

同格余弦上限取 0.95 的依据：开发集 64 个分格中，同格问句最大余弦的中位数为 0.776、
九十分位为 0.857、最大为 0.921（`UG_MAJOR_CHANGE/condition_missing`）。
若取 0.85，新建集合会比开发集本身更严，两者不可比；0.95 高于开发集的实测上限，
仍能拦住近乎逐字重复的问句。

## 三、预注册指标

主终点与次终点在跑之前定死；**报告时全部给出，不得按结果挑选**。

**主终点**

- `overall_success`：整体成功率。定义见 `SCORING_PROTOCOL_V2.md`（7 项精确等于 1 的合取）。

**次终点（按层组织）**

| 层 | 指标 |
|---|---|
| 检索 | `evidence_recall`、`citation_validity` |
| 流程 | `step_coverage`、`material_coverage` |
| 内容 | `answer_quality`、`claim_coverage` |
| 交互 | `response_mode_accuracy`、`follow_up_correct`、`missing_slot_f1` |
| 事项 | `item_correct` |
| 人工 | `task_completion_rate`（分层抽 60 条，三档判定） |
| 成本 | 调用次数、输入/输出 token、费用 |

## 四、预注册对照

在独立集上跑十二配置，与开发集口径完全一致。

### 修正说明二（2026-10-16，在任何系统于本集合成功运行之前）

2026-10-15 的第一次运行因接口额度耗尽而中止（服务端返回 HTTP 400 `Arrearage`），
其产出已作废并单独隔离，本集合上**尚无任何可用的系统结果**。本修正在此前提下作出，
未参考任何模型输出。

**修正原因**：原表把"对照2"定为"本项目方法去断言核验"、"对照3"定为"本项目方法去流程骨架"，
而判定规则又把主配置定为"骨架驱动决策"的版本。这样两组比较各自同时改变了两件事——
骨架的**有无**，以及骨架**放在哪里**（塞进生成提示词，还是只用于交互决策）。
因此原判据无法把效应归给"流程中间表示"或"断言核验"本身。涉及假设检验的比较已改为
同一套提示词设计内的对照，两组之间只差一个部件。

两个自变量：

- A 流程骨架：用于交互决策 / 不提供
- B 断言核验：无 / 弱形态（模型自行删句子）/ 强形态（逐条判定后确定性重组）

| 配置 | 骨架 | 核验 | 作用 |
|---|---|---|---|
| 基线A 向量检索加直接生成 | — | — | 朴素 RAG 下界 |
| 基线B 混合检索加重排序加引用 | — | — | 强检索基线 |
| 基线C 受限工作流（两步生成） | — | — | 强生成基线 |
| 对照1 基线C 加交互控制 | 不提供 | 无 | H3 的对照；分离"有交互控制"与"流程感知机制" |
| 本方法（骨架驱动决策）method_v2 | 用于决策 | 弱 | **主配置** |
| 对照2a 去流程骨架 ablation_v2_no_skeleton | 不提供 | 弱 | **H1 的干净对照** |
| 对照2b 去断言核验 ablation_v2_no_verify | 用于决策 | 无 | **H2 的干净下界** |
| 本方法（强核验）method_v3 | 用于决策 | 强 | **H2 的强形态** |
| 消融 去版本限定 ablation_no_version_limit | 用于决策 | 弱 | 版本限定对照 |
| 本方法（骨架入生成提示词）method | 入提示词 | 弱 | 原设计，作为设计间负对照 |
| 原设计去核验 ablation_no_verify | 入提示词 | 无 | 设计间对照，不用于判定 |
| 原设计去骨架 ablation_no_skeleton | 不提供 | 弱 | 设计间对照，不用于判定 |

**强形态的定义**：把草稿拆成互不重叠的原子断言，逐条判定其是否被本次检索到的证据直接支持；
只保留判为 `supported` 且给出证据编号的断言，按原顺序拼接，重组过程不经过模型改写，
被丢弃的断言不可能以改写的形式重新出现。判定只依据本次检索到的证据，
不使用流程记录中的任何人工标注。

**去追问拒答不再单列**：基线C 完全没有交互控制，H3 的对照（基线C → 对照1）已经覆盖
"能否追问、能否拒答"这一整块能力；主配置与去版本限定配置之间也不存在第二个交互部件，
单列会与该对照重复。

## 五、统计方案

- 配对比较：每条样本同一套题，逐样本配对差值。
- 显著性：符号随机化检验，10000 次重采样，小样本精确计数。
- 事项簇敏感性：以事项为簇做整簇重采样，检查结论是否由个别事项驱动。
- 多重比较：同一指标族内 Holm 校正。
- 显著性阈值：α = 0.05（**校正后**）。
- 区间：报自助 95% 区间，不只报点估计。
- 运行间波动已知：开发集上同一提示词仅调整换行即造成 0.01 量级差异。
  **因此只以配对检验下结论，点估计差值小于 0.03 不作解释。**

## 六、判定规则（跑之前写死）

| 假设 | 判据 | 成立条件 |
|---|---|---|
| **H3 交互控制** | 基线C → 对照1 的 `response_mode_accuracy` | Holm 校正后 p < 0.05 且方向为正 |
| **H1 流程中间表示** | 对照2a → 主配置 的 `overall_success` | Holm 校正后 p < 0.05 且方向为正 |
| **H2 断言核验（强形态）** | 对照2b → 强核验配置 的 `overall_success` | Holm 校正后 p < 0.05 且方向为正 |
| **版本限定** | 版本冲突子集上 去版本限定 → 主配置 的 `response_mode_accuracy` | Holm 校正后 p < 0.05 且方向为正 |

四条规则同属一个比较族，Holm 校正在这四条之内进行。

**判为不成立的情形**：p ≥ 0.05，或方向与预期相反。
不成立的假设按负结果报告，不换指标补救、不改用别的分层来说成立。

## 七、执行约束

1. **方法冻结在前**：独立集生成后先记下代码检查点，方法改动必须晚于该检查点并单独记录。
   本次的强形态核验与三处对照补齐属于检查点之后的改动，已在上文修正说明二中登记；
   它们发生在任何成功运行之前，因此不构成"看过结果再改方法"。
2. **一次性执行**：全部配置一次跑完，中途不因结果调整提示词、阈值、判分或样本。
3. **不得回头调参**：看过独立集结果之后，若改方法，必须在**新一批**样本上重测，
   不得在独立集上反复试。
4. **全部报告**：主终点、全部次终点、分层结果（按事项、按场景）与不利结果一并给出。
5. **样本不再改动**：独立集定稿后不因结果增删题目；发现标注错误时单独记录并说明影响。
