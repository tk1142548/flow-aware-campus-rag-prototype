# 表示口径审计：为什么撤回 2026-10-14 的第一轮结论

日期：2026-10-15
状态：已复核，结论已生效
影响范围：`ERROR_ANALYSIS.md` 中关于 H1 的判定、中期检查表"二、三"两栏的数字

---

## 一、为什么要撤回

第一轮对照得出"方法整体优于基线，但内容覆盖低于基线 B/C，H1 不成立"。复核判分链路后发现，
这个结论里混进了**两处表示空间不一致**的缺陷，性质与第一轮被清除的旧缺陷（判分要求输出
`claim_id`，导致任何生成式系统必然得 0）**完全相同**。这两处缺陷把 86 条样本（占 43%）
压成结构性 0 分。

因此第一轮的 H1 判定作废：它测的是缺陷，不是方法。

---

## 二、缺陷一：响应方式只有 4 档，金标准有 6 档

| 项 | 内容 |
|---|---|
| 位置 | `app/backend/systems.py` 的 `METHOD_USER` 与 `KNOWN_MODES` |
| 现象 | 提示词只提供 `answer / clarification / version_qualified / abstention`；金标准另有 `scoped_correction`、`conversation_resolution` |
| 覆盖面 | `scoped_correction` 72 条（36%）、`conversation_resolution` 24 条（12%） |
| 后果 | 方法**结构上不可能**输出 `scoped_correction`；判分要求模式精确匹配，于是这 72 条对方法恒为 0。基线 A/B/C 恒输出 `answer`，同样恒为 0 |
| 证据 | 72 条 `scoped_correction` 金标准，方法模式命中 **0/72**；其中 **30 条（41.7%）除模式外全部条件已满足** |

关键对照：`docs/data/STAGE_2_ANNOTATION_GUIDE.md` 第 59–64 行给出的映射是
`object_mismatch` / `step_error` / `material_confusion` → `scoped_correction`（3×24=72），
`multi_turn` → `conversation_resolution`（24）。即**金标准的响应方式是场景标签的确定性函数**，
而方法侧的实现当初漏了这两档。

修法：把 6 档写进提示词与 `KNOWN_MODES`，定义取自上述标注指南。修后定向抽查 13 条高风险样本，
方法已能产出 `scoped_correction`（命中 5/13，此前为 0）。

---

## 三、缺陷二：槽位按 ID 比较，系统输出自由文本

| 项 | 内容 |
|---|---|
| 位置 | `app/backend/scoring_v2.py` 的 `_slot_f1(gold["missing_slot_ids"], prediction.missing_slot_ids)` |
| 现象 | 金标准是 7 个闭集 ID（`SL_REQUEST_TYPE` 等），系统输出自然语言（"需要打印的证明类型"） |
| 覆盖面 | 32 条要求追问的样本 |
| 后果 | 两个集合**交集恒为空**，`missing_slot_f1` 恒为 0，而它是 `overall_success` 的 7 个合取项之一 → 这 32 条对任何系统恒为 0 |
| 证据 | 金标准取值 `{SL_REQUEST_TYPE, SL_WITHDRAWAL_TYPE, SL_DOCUMENT_TYPE, SL_LOSS_STATUS, SL_TERM_PHASE, SL_LEAVE_DAYS, SL_APPLICANT_TYPE}`；预测取值全部为中文自由文本；交集为空集 |

修法：新增 `resolve_gold_slot_names()`，把金标准 ID 解析为槽位 `name`（如 `SL_REQUEST_TYPE` → "办理类型"），
再按内容匹配计算 F1；`_slot_f1` 已删除。修后同一样本上"办理类型"可被正确匹配，
未命中的剩余 0 分是真实失败（确实没问到该槽位）。

## 五、修掉缺陷后仍然成立的结论

以下与判分口径无关，是硬差距，不得因上面的修正而被忽略：

| 指标 | 基线 C | 方法 | 差 |
|---|---|---|---|
| `answer_quality`（内容覆盖） | 0.7564 | 0.6817 | **−0.0748** |
| `claim_coverage` | 0.8167 | 0.7423 | **−0.0743** |
| `step_coverage` | 0.7926 | 0.7565 | −0.0361 |
| `response_mode_accuracy` | 0.2800 | 0.5650 | +0.2850 |
| `follow_up_correct` | 0.8400 | 0.9500 | +0.1100 |

即：加进流程骨架与断言核验之后，**内容覆盖确实下降**，交互控制确实提升。这条张力是真实的，
不是口径造成的。

---

## 六、这次暴露的方法论缺口（防止重犯）

1. **判分口径的每一个条件都要先用"系统能表达的表示"验证一遍。** 旧缺陷（`claim_id`）已修，
   但同一类错误在 `missing_slot_ids` 上原样复现了一次。今后新增任何判分条件，先写一条
   "随便一个生成式系统能拿到满分吗"的测试。
2. **缺陷修好之后才能谈删机制。** 在两个缺陷修好之前，"机制无效"的结论是不成立的；
   同样，修好之后的数字才是可以据以决策的数字。
3. **所有反事实重算必须标注为反事实。** 上面的 0.440 是在旧预测上换口径算出来的，
   不能写进报告当结论。
