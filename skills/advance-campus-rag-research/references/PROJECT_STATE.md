**两处已修复的缺陷（今后新增任何判分条件都要先过这一关）**

1. 方法侧响应方式只实现了 4 档，金标准有 6 档。`scoped_correction`（对象错配/步骤错误/材料混淆，
   72 条）在方法侧**不存在**，对四配置恒为 0。
2. `missing_slot_f1` 拿金标准的闭集 ID（`SL_REQUEST_TYPE` 等）与系统输出的自由文本做集合交，
   交集恒为空，32 条追问样本对任何生成式系统恒为 0。

| 配置 | 整体成功率 | 响应方式 | 内容覆盖 |
|---|---|---|---|
| 基线A（向量检索+直接生成） | 0.110 | 0.280 | 0.442 |
| 基线B（混合检索+重排序+引用） | 0.165 | 0.280 | 0.761 |
| 基线C（受限工作流） | 0.180 | 0.280 | 0.780 |
| 无骨架（C + 交互控制） | **0.395** | **0.770** | 0.728 |
| 方法（原设计：骨架进生成提示词） | 0.270 | 0.710 | 0.605 |
| 无核验 | 0.265 | 0.710 | 0.597 |
| **方法（改造后 method_v2：骨架只驱动决策）** | **0.375** | 0.725 | 0.775 |

**结论（八配置，200 条开发集；必须按此口径对外表述）**

八配置成绩：基线A 0.110 / 基线B 0.165 / 基线C 0.180 / 无骨架 0.290 / 方法(原设计) 0.270 /
无核验 0.265 / **方法(改造后 method_v2) 0.375** / **无骨架+无核验 0.395**。

1. **交互控制是唯一成立且幅度大的贡献。** 基线C → 无骨架对照：整体 **+0.2150**（48 胜 5 负，
   p=0.0001），响应方式准确率 **0.280 → 0.770**（104 胜 6 负，p=0.0001）。
   它使原本完全做不到的四类行为变为可行：范围纠正 0 → 0.611、追问 0 → 0.969、
   版本限定 0 → 0.792、越界拒答 0 → 0.625。
2. **流程骨架（塞进生成提示词）没有任何正效应。** 无骨架 → 方法(原设计)：
   整体 −0.0200（12 胜 16 负，p=0.58），模式 −0.0350，均在噪声内。
3. **断言核验目前没有效应。** 无核验 → 方法：+0.0050（2 胜 1 负，p=1.0）。
   注意：这是"让模型删掉无据句子"的弱形态；基于流程声明的强形态尚未实现、尚未检验。
4. **把流程骨架改为只驱动交互决策（method_v2）能挽回 +0.1050**（29 胜 8 负，p=0.0011；
   内容覆盖 +0.1707，p=0.0001）。但它相对"完全不用骨架"的对照仍是 −0.0200（p=0.58），
   即：**骨架放进生成提示词是有害的，拿出来之后只是不再有害，尚未证明有益。**
5. **H1 现在的判定：在已测的两种设计下均未观察到正效应。** 不得对外宣称流程中间表示有增益；
   可宣称的是它作为交互决策的依据而存在。
6. **运行间波动必须记住**：基线C 的 prompt 仅重排换行即从 0.170 变为 0.180。
   小于 0.03 的差值不可靠，任何结论都要看配对检验而不是点估计。
7. **过期入口未解决**：专门构造的题上各配置均未选 `version_qualified`。
8. 对外表述一律用"开发集"，并说明它已参与调参、不构成确认性证据。
